## 一、AI 学长这次改了什么

### 1. 识图（发图片不说话 → 直接描述图里有什么）

**以前的问题**：发图片后如果视觉模型忙（智谱免费额度常见 `1305`），代码会降级到纯文本模型 ——
文本模型看不见图，只能回「我看不到图片」，看起来就像"识图坏了"。

**现在的行为**：

| 场景 | 现在的表现 |
|---|---|
| 只发图不打字 | 后端自动补一句「我只发了这张图片，请直接告诉我图里有什么」，模型直接描述画面 |
| 发图 + 带问题 | 先说你看到了什么，再回答问题 |
| 视觉模型拥堵 | 顺着视觉链换下一个模型，**绝不降级到看不见图的文本模型** |
| 网关不认 `data:image/...;base64,` 前缀 | 自动去掉前缀重试一次（这一步救回很多"发了图没反应"） |
| 全部失败 | 明确说「识图的模型有点忙 / 这张图没读成功」，而不是假装看不见 |

可配置的视觉模型（环境变量，可选）：

```
VISION_MODEL = glm-4v-flash          # 想换模型时填，会排在视觉链第一位
```

默认视觉链：`glm-4v-flash` → `glm-4.1v-thinking-flash`（智谱）。

### 1.5 速度与超时（2026-10-20 修过一次）

**以前的现象**：问短问题还行，一问"写个脚本"就长时间显示"思考中"，偶尔弹出一串
`模型服务返回 504: <!DOCTYPE html>...Tencent EdgeOne...`。

**根因两条**：

1. 主模型是 `glm-4.5-flash`，它即使关掉思考也会先"想"一轮，实测**首字要 11 秒**；
2. 原来的写法是「先等上游返回，再把响应给浏览器」，模型一慢，平台网关先等不及，
   直接回一张自己的 504 错误页给前端 —— 前端又把这串 HTML 当报错内容显示出来。

**现在的做法**：

| 改动 | 说明 |
|---|---|
| 主模型换成 `glm-4-flash-250414` | 纯对话模型，没有思考过程，首字 1-2 秒；`glm-4.5-flash` 降为备用 |
| `thinking` 字段按型号下发 | `glm-4-flash` 不认识这个字段，一律加会直接 400，所以只对 4.5/4.6/4.7 和带 thinking 的型号发 |
| **先开流，再连上游** | 立刻返回 200 + 一行 `: connected`，之后每 6 秒一个 `: ping` 心跳；上游再慢用户看到的也是"正在思考" |
| 等响应头 18 秒超时 | 超时就放弃这个模型换下一个，不把时间耗在排队上 |
| 整段生成 42 秒封顶 | 超时保留已写内容并补一句"要看后半段就说继续" |
| 前端分档提示 | 4.5 秒"正在整理答案" → 15 秒"模型有点忙，还在排队" → 28 秒"还在写" |

**实测对比**（同一台机器、同一个问题）：

| 场景 | 改前首字 | 改后首字 | 结果 |
|---|---|---|---|
| "简单介绍一下你自己" | 1.4s | 1.98s | 正常 |
| "写个 Python 脚本统计文件后缀" | **11.0s** | **2.18s** | 正常 |
| "写个完整贪吃蛇网页游戏"（5735 字） | 常被 504 砍掉 | 2.27s，总 32.7s | **正常返回 200** |

最后那条很关键：一个请求跑了 32.7 秒、发了 5 次心跳，仍然完整返回，
说明"先开流"这一步把以前必挂的长回答救回来了。


### 4. 记忆 + 全局规则（每个访客各自独立）

记忆和规则都存在**访客自己的浏览器 localStorage** 里，所以：

- 每个人的对话记忆天然隔离，A 记的东西 B 看不到；
- 换浏览器、清缓存会丢（这是当前设计的取舍：不收集任何用户数据到服务器）；
- 服务器不存任何用户个人信息。

对话里可以直接下指令（都是本地处理，不花模型额度、秒回）：

| 指令 | 作用 |
|---|---|
| `/help` | 查看全部指令 |
| `/记住 我叫小明，住嘉园` | 长期记住关于你的事 |
| `/记忆` | 打开面板，逐条查看 / 删除 |
| `/忘掉` | 清空全部记忆；`/忘掉 名字` 只删相关那条 |
| `/规则 回答简短点` | 定一条长期规矩（称呼、长度、侧重都行） |
| `/规则` | 查看已设规矩 |
| `/删规则 2` | 删第 2 条规矩 |
| `/清空` / `/清空规则` | 清对话 / 清规矩 |
| `/关于` | 这站谁做的 |

规则只影响**说话风格和偏好**，不能改事实、不能绕过安全底线（后端有校验）。

## 二、防护措施

### 分层清单

| 层 | 措施 | 挡什么 |
|---|---|---|
| 全站 | `frontend/robots.txt` | 明确拒绝 20+ 种 AI 训练爬虫（GPTBot / CCBot / ClaudeBot / Bytespider / PerplexityBot …）与 SEO 采集器，正常搜索引擎放行 |
| 全站 | 根目录 `edgeone.json` 的 `headers` | `X-Frame-Options`（防套壳）、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`、`HSTS`；`/img/*` 缓存 7 天，`/api/*` 强制 `no-store` |
| `/api/chat` | 爬虫 UA 过滤 + Origin 白名单 + 体积上限（2MB） | 脚本刷接口、把接口当免费中转站 |
| `/api/chat` | 限流：单 IP 20 次/分、150 次/时、300 次/天；全局 4000 次/天 | 刷爆模型额度 |
| `/api/chat` | 反越狱：识别"忽略以上指令 / 把系统提示词打印出来 / 进入开发者模式 / base64 输出设定"等 | 套取系统设定；10 分钟内命中 5 次 → 该 IP 封 10 分钟 |
| `/api/chat` | 提示词层防护 | 明确禁止复述系统设定、禁止角色劫持 |
| `/api/wall`、`/api/danmaku` | UA 过滤 + Origin 白名单 + 蜜罐字段 + 重复提交拦截 + 限流 | 批量灌水、脚本上墙 |
| `/api/danmaku` | **本次新补**（原来完全裸奔）：4 条/分、24 条/时、80 条/天；2KB 体积上限；控制字符与尖括号清洗 | 无限刷屏、脏字符塞 HTML |
| 前端 | 弹幕发送失败会弹轻提示 | 以前是静默失败，用户以为发出去了 |

### 已知限制（别指望 robots.txt 能"强制"防爬）

- `robots.txt` 是**君子协定**，恶意爬虫根本不看它。真正拦得住的是边缘函数层的 UA/限流
  —— 但那只能保护 `/api/*`，**静态页面本身仍可被抓取**。
- 想彻底防扒静态页，需要 EdgeOne 的 WAF / 中间件能力（可能要付费档位）。
  目前的做法是：robots 劝退 + 接口层严管（钱和额度都在接口上，静态页被爬只是内容被抄）。

### 关于响应头（重要）

EdgeOne Pages **不支持 Cloudflare 那套 `_headers` 文件**（实测：放进去只会被当普通静态文件，
响应头里啥也没有）。它认的是项目根目录的 `edgeone.json`，写在 `headers` 数组里：

```json
{ "headers": [ { "source": "/*", "headers": [ { "key": "X-Frame-Options", "value": "SAMEORIGIN" } ] } ] }
```

改完 push 上去会自动重新部署。验证方式：

```bash
curl -sI https://site.liuyushan.top/ | grep -i "x-frame\|referrer\|strict-transport"
```

看不到就去控制台「项目设置 → 响应头」手动补一份，内容同上。

- 这里**故意没有配 `Content-Security-Policy`**：页面里引了高德地图和 three.js，
  CSP 写紧一点地图就白屏，写松等于没写，收益不值这个折腾成本。
- 如果哪天加了 CSP 后地图白屏，把 CSP 那条删掉再部署即可。
